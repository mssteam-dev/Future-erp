# النظام المحاسبي — شركة أم وثلاثة فروع

برنامج محاسبي وإداري متكامل، عربي بالكامل واتجاهه من اليمين إلى اليسار، مبني وفق
وثيقة المواصفات: إدخال العملية مرة واحدة، ثم تتحدث المخزون والصندوق والبنك والذمم
والأرباح والتقارير تلقائيًا، بلا ازدواجية احتساب.

## التشغيل على ويندوز (الأسهل)

1. ثبّت **Node.js 22** من nodejs.org و**PostgreSQL 16** من postgresql.org
   (احفظ كلمة مرور مستخدم `postgres` التي يطلبها المثبّت).
2. اضغط مرتين على **`setup.bat`** — يفحص الخادم، ويهيّئ قاعدة بيانات محلية إن لزم،
   ويطبّق المخطط ويثبّت المكتبات وينشئ مستخدم الدخول.
3. اضغط مرتين على **`start.bat`** — يشغّل النظام ويفتح المتصفح على
   `http://localhost:3000`.

كل مرة لاحقًا: `start.bat` فقط.

## التشغيل اليدوي (لينكس/ماك أو تفضيلًا لسطر الأوامر)

```bash
# 1) متطلبات: Node 22+ و PostgreSQL 16+
npm install

# 2) إعداد الاتصال
cp .env.example .env.local        # ثم عدّل DATABASE_URL و SESSION_SECRET

# 3) بناء قاعدة البيانات (ينشئها من الصفر ويطبّق كل المايجريشن)
bash scripts/db-reset.sh

# 4) إنشاء مستخدم المالك
node scripts/create-user.mjs admin "كلمة-مرور-قوية" "مدير النظام" --owner

# 5) التشغيل
npm run dev        # للتطوير
npm run build && npm start   # للإنتاج
```

لتحميل بيانات تجريبية للتجربة قبل الاعتماد:

```bash
psql -d erp_dev -f scripts/seed-demo.sql
```

## الاختبار

```bash
bash scripts/test.sh          # ٣٠٥ تأكيدات على المعادلات والقواعد في قاعدة بيانات نظيفة
npx tsx scripts/smoke.ts      # فتح كل شاشات النظام والتأكد من سلامتها
npx tsx scripts/e2e.ts        # دورة عمل كاملة من الواجهة: بيع، تحصيل، مصروف، تحقق
npx tsx scripts/e2e-new.ts    # الميزات الجديدة من الواجهة: شحنة، مدفوع مقدمًا، أرصدة افتتاحية، Excel
npx tsx scripts/e2e-website.ts  # قسم الموقع الإلكتروني: المنيو، الفروع، الصلاحيات، ما يقرؤه الموقع
```

كما توجد شاشة **الإعدادات ← النسخ الاحتياطي** تعرض ستة عشر فحصًا لسلامة البيانات
(توازن القيود، مطابقة المخزون للدفتر، مطابقة الذمم، حيادية التحويلات…) يمكن
تشغيلها في أي وقت.

## البنية

```
supabase/migrations/   مخطط قاعدة البيانات ومنطق الترحيل (PL/pgSQL)
supabase/tests/        مجموعات الاختبار بأرقام محسوبة يدويًا
src/app/(app)/         شاشات النظام
src/components/        مكونات الواجهة والمستندات والمخططات
src/lib/               الاتصال بقاعدة البيانات، المصادقة، الصلاحيات، الإجراءات
scripts/               إعداد القاعدة، المستخدمين، النسخ الاحتياطي، الاختبارات
```

**التقنيات:** Next.js 16 + TypeScript + Tailwind v4 + PostgreSQL 16.
التطبيق يتصل بقاعدة البيانات بدور `authenticated`، فتُطبَّق عليه سياسات RLS كاملة.
يعمل على أي Postgres، ومنها Supabase (اضبط `PGSSL=require`).

## كيف يمنع النظام ازدواجية الاحتساب

هذا هو الشرط الأكثر تكرارًا في الوثيقة، وقد عولج بنيويًا لا بالاتفاق:

| القاعدة | التنفيذ |
|---|---|
| مصدر واحد للأرقام | كل أثر مالي يُسجَّل مرة واحدة في `journal_lines`، وكل التقارير تُقرأ منه |
| المستند لا يُرحَّل مرتين | فهرس فريد على (نوع المستند، معرفه) في جدول القيود |
| الدفاتر لا تُكتب من الواجهة | الكتابة في القيود وحركات المخزون عبر دوال `SECURITY DEFINER` فقط |
| التحصيل ليس إيرادًا | قيد التحصيل يمس النقدية والذمم فقط، ويُفحَص آليًا |
| تحويل البضاعة ليس بيعًا | مدين مخزون الفرع / دائن مخزون الشركة الأم — صافي الأثر صفر |
| التحويل بين الصندوق والبنك | حركة واحدة بطرفين، بلا إيراد ولا مصروف |
| المصاريف الإدارية | تُسجَّل مرة واحدة على الشركة الأم، والتوزيع على الفروع يُحتسب في التقارير ولا يُرحَّل |
| الفاتورة الآجلة | لا تدخل الصندوق قبل تحصيلها، ويُرفض فتح ذمة لعميل نقدي |
| دفع المورد | يخفض الذمة والنقدية فقط، بلا تسجيل مشتريات جديدة |

## قواعد محاسبية مطبّقة

- **تقييم المخزون:** FIFO افتراضيًا (الأقدم أولًا، كل دفعة بتكلفتها النهائية)، مع
  خيار المتوسط المرجح المتحرك من **الإعدادات ← طريقة تقييم المخزون**. في الحالتين
  قيمة المخزون وعاء تكلفة تتحرك بنفس مبالغ القيد، فلا ينشأ فرق تقريب بين تقرير
  المخزون والدفتر.
- **مصاريف الشحنة** تُوزَّع على أصناف الشحنة بالتساوي على القطع أو بالوزن أو بالقيمة،
  ولكل مصروف أساس توزيع مستقل، ومجموع الموزَّع يساوي المصروف بالضبط (فرق التقريب
  يُحمَّل على أكبر سطر). كل شحنة مستقلة عن غيرها.
- **الضريبة المحصلة** التزام للجهة الضريبية، لا إيراد للشركة.
- **المخزون السالب** مرفوض ما لم يُفعَّل الإذن من الإعدادات.
- **الفترة المقفلة** ترفض أي ترحيل، والشهر التالي يُفتح تلقائيًا بأرصدة مرحَّلة.
- **لا قروض** في النظام: لا شاشة ولا جدول ولا تقرير.

## الجهات المستقلة والمنتجات

الشركة الأم والفروع الثلاثة جهات مستقلة: لكل جهة **بطاقات منتجاتها** (الكود فريد داخل
الجهة، ويجوز تكراره بين جهتين) ومخزونها وتكلفتها ومشترياتها ومبيعاتها ومصروفاتها
وتقاريرها. عند تحويل بضاعة إلى فرع تُنشأ له بطاقة المنتج تلقائيًا إن لم تكن
موجودة، وتنتقل دفعات التكلفة كما هي: **التحويل بسعر التكلفة الأصلية بلا ربح وهمي**.

بطاقة المنتج تعرض: المورد، سعر الشراء الأساسي، الشحن المحمَّل، التكلفة النهائية،
سعر البيع، الوزن، الكمية المتاحة والمباعة والمرتجعة، وقيمة المخزون.

## الشحنات

الشحنة هي فاتورة شراء بتفاصيل إضافية: رقم الشحنة، جهة الشحن، وزن كل صنف، ومصاريفها
(شحن، تخليص جمركي، نقل، تأمين، أخرى) ولكل مصروف جهة سداد وأساس توزيع.
تُعرض **التكلفة النهائية بعد توزيع المصاريف** قبل الحفظ. التقارير: **الشحنات**
و**تكلفة المنتجات** و**دفعات المخزون**.

## المصروفات المدفوعة مقدمًا والإقفال الشهري

- مصروف يُدفع دفعة واحدة ويُوزَّع على أشهر محددة (**المصروفات ← مدفوع مقدمًا**)،
  وتُحمَّل الأقساط تلقائيًا عند **إقفال الفترة** أو يدويًا بزر «تحميل الأقساط»،
  ولا يُحمَّل الشهر نفسه مرتين.
- **مصاريف تكلفة الشراء** (شحن، جمارك…) تدخل في تكلفة المخزون، وتُفصل في التقارير عن
  **المصاريف التشغيلية** التي تُحمَّل على الأرباح.
- **الإقفال الشهري** يرحّل الأقساط المستحقة ويقفل الفترة ويفتح الشهر التالي بأرصدة
  مرحَّلة (تقرير **إقفال الفترة**).

## الأرصدة الافتتاحية

شاشة واحدة (**الإعدادات ← الأرصدة الافتتاحية**) للنقدية والبنوك والمخزون وأرصدة
العملاء والموردين وأي أرصدة مدينة أو دائنة أخرى. تُسجَّل كأرصدة افتتاحية مقابل حساب
حقوق افتتاحية، **ولا تُعدّ إيرادًا**، ويُرفض تكرار الرصيد لنفس الطرف والجهة.

## تصنيفات المنتجات

شجرة تصنيفات حتى **خمسة مستويات** (تصنيف رئيسي وتحته فروع). الحدّ مفروض في قاعدة
البيانات نفسها، ومعه منع الدوران (نقل تصنيف إلى أحد أبنائه) ومنع حذف تصنيف مرتبط
بمنتجات أو له فروع.

تُدار من **المنتجات ← تصنيفات المنتجات**، وتصفية قائمة المنتجات بتصنيف رئيسي تشمل
كل ما تحته.

## صور المنتجات

لكل منتج صورة اختيارية تُرفع من شاشة **المنتجات ← تعديل**. الصورة تُصغَّر في المتصفح
قبل الرفع (نحو ٤ كيلوبايت للصورة) وتُحفظ داخل قاعدة البيانات، فتدخل في النسخ
الاحتياطي ولا تعتمد على مجلد خارجي قد يُفقد عند النقل.

الصور تظهر في:

- **منتقي المنتجات** في فواتير المبيعات والمشتريات والتحويلات والجرد — بحث بالاسم
  أو الكود، مع صورة الصنف ورصيده المتاح وسعره، بدل القائمة المنسدلة التي يسهل
  الخلط فيها بين الأصناف المتشابهة
- قائمة المنتجات وتقرير أرصدة المخزون

## التقارير

التقرير المالي لكل فرع ببنوده الستة عشر، التقرير الموحَّد، ملخص الشركة الذي يفصل
إيراد الشركة الأم عن مبيعات الفروع ويعرض الربح قبل إضافته وبعده، أعلى ١٠ منتجات
مبيعًا وربحًا، ربحية المنتجات، بطاقة حركة المنتج، كشوف حسابات العملاء والموردين،
كشوف الصناديق والبنوك، ميزان المراجعة، تقرير التحصيلات وأعمار الذمم.

وأضيف: الشحنات، تكلفة المنتجات، دفعات المخزون، المدفوع مقدمًا، المصاريف التشغيلية،
التحويلات بين الجهات، إقفال الفترة، و**التقرير المجمّع** الذي يفصل الإيراد الخارجي
عن التحويلات الداخلية ويحسب المصاريف الإدارية مرة واحدة.

كل تقرير قابل للطباعة أو الحفظ PDF من المتصفح (تنسيق طباعة مستقل)، وللتصدير إلى
**Excel (.xlsx)** حقيقي أو CSV.

## الصلاحيات

المالك يملك كل الصلاحيات. بقية المستخدمين يأخذون صلاحياتهم من أدوار (مدير عام،
محاسب، مدير فرع، أمين صندوق، مشاهدة فقط) مع تحديد الفروع المسموح لهم بها. كل
العمليات تُسجَّل في سجل العمليات.

## الموقع الإلكتروني

قسم مستقل عن المحاسبة يُدار منه محتوى الموقع العام: **منيو الموقع والأسعار** (أقسام
وأصناف بالعربية والإنجليزية، سعر، ملاحظة، ترتيب، إظهار وإخفاء) و**فروع الموقع وساعات
العمل** (عنوان، هاتف، رابط خريطة، ساعات كل يوم).

- الجداول `site_*` لا علاقة لها بالمنتجات ولا المخزون ولا القيود (المايجريشن 0020).
- الصلاحيتان `website.view` و`website.edit`، ودور **محرر الموقع** لا يملك غيرهما:
  قاعدة البيانات لا تعيد له أي بيانات محاسبية، ويبدأ من قسم الموقع مباشرة.
- الموقع يقرأ المحتوى الظاهر فقط من `/api/public/website` بلا تسجيل دخول، مع تخزين
  مؤقت قصير، فيظهر التعديل فيه خلال دقيقتين تقريبًا.
- كل تعديل يُسجَّل في سجل العمليات، وتعديل السعر يُسجَّل بالسعر القديم والجديد.

## النسخ الاحتياطي

```bash
DATABASE_URL=postgres://... bash scripts/backup.sh /path/to/backups
```

يحتفظ السكربت بآخر ٣٠ نسخة، وتُسجَّل النسخ في شاشة النسخ الاحتياطي للتوثيق.

## ما يُضبط لاحقًا

- اسم الشركة وأسماء الفروع وبياناتها: **الإعدادات ← إعدادات الشركة / الفروع**
- اللوجو ولون الهوية: **الإعدادات ← إعدادات الشركة**
- بادئة ترقيم المستندات وعدد الخانات: جدول `document_sequences`
